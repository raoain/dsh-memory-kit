# 踩过的坑（脱敏版）

这些坑都是真踩出来的，按「现象 / 根因 / 修法」记。凡是能复现的，都写了怎么复现。

判断一个坑值不值得记：**下次撞上它，我会不会浪费半小时以上**。会，就写下来。

---

## 1. 中文文件读出来是乱码，看着像文件损坏

**现象**：`Get-Content` 读出来是 `鏍稿績灞?`、`姣忔閱掓潵`，`ConvertFrom-Json` 报「应为 `:` 或 `}`」。

**根因**：PowerShell 5.1 对**没有 BOM** 的 UTF-8 文件默认按 GBK(936) 解码。文件本身是好的。

**修法**：

```powershell
Get-Content $p -Raw -Encoding UTF8
[IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
```

**先验字节，再动手改文件** —— 用严格解码器，抛异常才是真坏：

```powershell
$dec = [Text.Encoding]::GetEncoding('utf-8',
    [Text.EncoderFallback]::ExceptionFallback,
    [Text.DecoderFallback]::ExceptionFallback)
$dec.GetString([IO.File]::ReadAllBytes($p))
```

**为什么危险**：误判成「文件损坏」之后，人会去重写文件、甚至重装。我因此浪费过一整天。

## 2. 编辑工具会吃掉 BOM，`.ps1` 直接语法崩

**现象**：`powershell -File xxx.ps1` 报一串 `Unexpected token` / `Missing closing ')'`，报错里的中文是乱码。

**根因**：多数编辑/写文件接口按无 BOM 的 UTF-8 写。脚本丢了 BOM，PS 5.1 就按 ANSI 解析，中文全碎，语法跟着崩。

**修法**：改完 `.ps1` 立刻补回 BOM 再跑一次。

```powershell
$p = '<你的脚本>.ps1'
$t = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
if ($t[0] -eq [char]0xFEFF) { $t = $t.Substring(1) }
[IO.File]::WriteAllBytes($p, (New-Object Text.UTF8Encoding($true)).GetPreamble() + [Text.Encoding]::UTF8.GetBytes($t))
```

**识别法**：报错里中文是乱码 + 一堆 token 错误 = BOM 丢了，**不是语法写错**，别去改代码。

## 3. 插件装了不等于会加载

**现象**：依赖装好了、`node_modules` 也在，但工具就是不出现，且**没有任何报错**。

**根因**：宿主只挂载配置文件里 `bundles` 列出的插件；只写进依赖列表不算。

**修法**：排查顺序

1. 配置里的 `bundles` 有没有它
2. `node_modules` 里有没有链接/实体
3. 入口导出形状（具名 `apply` 与 `default` 两种都提供，宿主两种都认）

---

## 4. 把 git 仓库链进 node_modules，`.git` 会被弄坏

**现象**：仓库 HEAD/config 消失，只剩空的 `objects/`、`refs/`。

**根因**：包管理器处理本地路径依赖时，会穿过 junction / 链接操作目标目录。

**修法**：

- 用 `file:` 安装，不要用 `link:`
- 源码仓库和 `node_modules` 保持**物理分离**
- 随时保证远端有备份 —— 就是靠远端救回的提交

---

## 5. 启动 Electron 程序，它静默退出、退出码 0、没有日志

**现象**：双击能开，脚本里 `Start-Process` 启动就立刻退出，日志一行不写。

**根因**：如果父进程本身是 Electron（很多 IDE/桌面应用都是），环境里可能带着 `ELECTRON_RUN_AS_NODE=1`。子进程继承后**退化成纯 Node**，只跑 Node 逻辑，不开窗口。

**修法**：启动前清掉该变量。

```powershell
Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
```

**判断法**：`--version` 输出的是 Node 版本而不是应用版本，就说明它退化成了 Node。

---

## 6. 同一目录的两个路径字符串，包管理器不认

**现象**：`ERR_PNPM_UNEXPECTED_STORE`，说依赖来自另一个 store 位置。

**根因**：目录是 junction / 符号链接，两个路径指向同一份数据，但包管理器按**路径字符串**判断，认为 store 变了。

**修法**：用和安装时**完全相同**的路径字符串启动，不必重装依赖。

---

## 7. 备份只覆盖「目录」，漏了目录之外的单文件

**现象**：重装后，文件夹里的东西都在，但检索库、密钥文件全没了。

**根因**：备份脚本只打包一个目录，而关键单文件在它的兄弟目录里。这类文件平时不看，最容易漏。

**修法**：备份脚本加一个「额外单文件」列表，跟目录一起轮转、一起落两块盘。

---

## 8. 重装只换程序，不还原数据目录

**现象**：程序回来了，记忆是空的。

**根因**：安装器只覆盖程序目录；数据目录通常在别处（用户目录 / 程序旁的 `data`），安装器不碰，也不会帮你还原。

**修法**：重装后**主动**从备份解压回数据目录，并清掉过期的实例锁文件（否则新进程会以为自己已在运行而退出）。

---

## 9. 日志统计不要用「某一行」当锚点

**现象**：自检报的扩展数量时多时少。

**根因**：日志里启动标记会重复出现多次（每次重启都有一条）。拿最后一次当锚点，会漏掉它之前启动的；拿第一条当锚点，会混进上一次的。

**修法**：不设锚点，整段取匹配项按名字去重。

---

## 10. `git push` 被重置，但 API 能用

**现象**：`git push` 报 `Recv failure: Connection was reset`，fetch 也一样。

**根因**：网络对 443 的 git 流量不稳定，但带 token 的 API 请求正常。

**修法**：用 CLI 的 API 能力逐文件提交，或直接用 git data API（blob → tree → commit → ref）做**一个**完整提交，别散成一堆碎提交。

注意：用 API 传 `.ps1` 时要 `encoding=base64` 原样传字节，否则 BOM 会丢（见第 2 条）。

---

## 11. 参数被同名变量覆盖：改了但不生效

**现象**：给脚本加了参数、改了默认值，跑出来还是旧结果。没有报错。

**根因**：PowerShell 变量名**不区分大小写**。参数 `$Voice` 与脚本内部的 `$voice` 是同一个变量；后续赋值把参数盖掉了。函数名同理（`H` 会撞上内置别名 `h = Get-History`）。

**修法**：

- 参数与内部变量一律加明确前缀（`TtsVoice`、`Get-CacheKey`），不要只靠大小写区分
- 参数名不要和脚本里任何已有变量同名；改完搜索一遍 `$参数名` 确认只有声明处
- **用可观测证据验证是否真的生效**：缓存键、文件哈希、输出内容 —— 不要看界面「好像变了」

---

## 12. 「拿副本试刀」没验隔离，砍了真文件

**现象**：想先在副本上测试一个会改文件的脚本，结果真文件被改了。

**根因**：`-Root` 参数没生效（见第 11 条），脚本内部仍有硬编码路径，于是「副本测试」实际操作的是真目录。

**修法**：

```powershell
$real = 'F:\path\to\real.md'
$before = (Get-FileHash $real).Hash
# … 在副本上跑测试 …
$after = (Get-FileHash $real).Hash
if ($before -ne $after) { throw '隔离失败：真文件被动了' }
```

跑前记哈希、跑后比对，是最便宜的隔离断言。任何「我先在副本上试一下」的操作都该这么写。
---

## 13. 作废的旧结论还躺在旧文件里（幽灵规矩）

**现象**：明明已经改过规矩，下次却照着旧的做了。比如上限早就改了，却按旧上限少发一条；某功能早就是要装扩展，却以为内置。

**根因**：删除不管用。删掉的只是「现在」，旧笔记、旧文档、旧草稿里的那句还在。读到它，就照着错的做。

**修法**：单独建一份墓碑（`templates/tombstones.md`），三行一条：什么时候作废 / 为什么 / 现在按什么来。

- **入库门槛**：只收「读到会让人立刻做错事」的；版本号变更、措辞调整不算
- **和垃圾场的区别**：墓碑管作废的规矩，垃圾场管不要的物理文件
- 这句判断要写进纪律里：**不编、不藏、不标死不算完**

---

## 14. 自查只靠「想起来就查」

**现象**：每次都觉得「刚才查过了」，但换一个窗口就说不清查了什么、结果是什么。

**根因**：检查项留在脑子里，没有落成脚本和输出。没有落成数据，就等于没发生。

**修法**：写一个 `scripts/verify.ps1`，把可核对的事实一次跑完（核心层大小、墓碑条目、留痕时效、双盘备份、检索库体积、规则文件 BOM、最近快照），输出 OK / WARN / FAIL。

**关键约束：必须便宜到随手能跑（<5 秒）**，否则不会跑。慢的检查（联网核查发布状态）放在 -Deep 里默认关。
---

## 15. `git reset --hard origin/main` 退回到很旧的版本

**现象**：想「和远端同步」，结果工作区被甩回很早的提交：README 变旧、新加的文件消失。

**根因**：网络抓不动 GitHub（443 被重置）时 `git fetch` 失败，但 `origin/main` 这个本地缓存 ref 仍然存在——它指向上次抓到的提交，可能很旧。`reset --hard` 照着它执行，等于把工作区退回去。

**修法**：

- reset 前先比对：`origin/main` 的 sha 与远端真实 `commits/main` 是否一致（用能通的方式取，比如带 token 的 API）
- 不一致就别 reset；要恢复内容，用 API **逐文件**下载（`contents/<path>` → base64 解码），不要用 tarball
- 本地仓库和远端长期分叉时，宁可新建一个干净仓库，也不要在旧仓库上 reset

---

## 16. 变量为空时，`"\*"` 会变成整个盘

**现象**：一条「解压后复制」的命令，把 C 盘根目录（Boot、Windows 相关目录……）拷进了项目仓库。

**根因**：解压失败 → `` 是空字符串 → `"`\*"` 变成 `"C:\*"` → `Copy-Item -Recurse` 忠实地照做。PowerShell 不会因为这个路径「看起来很怪」而停手。

**修法**：

- 解压/下载后**先断言结果**：目录存在、非空、里面有预期文件
- 任何递归复制前 `Join-Path` + `Resolve-Path`，校验结果落在预期父目录下
- 对 `` / 空字符串做显式检查：`if ([string]::IsNullOrWhiteSpace()) { throw }`

## 17. 给 JSON 补 BOM，插件直接变 error

**现象**：插件装好了、文件都在，但 `list_bundles` 里它显示 `availability: error`，diagnostic 写着
`Unexpected token '﻿', "{ ... is not valid JSON`（那个不可见字符就是 BOM）。

**根因**：`.ps1` 需要 BOM（PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 读），但 **JSON 解析器不接受 BOM**。
把「脚本要补 BOM」的习惯顺手用在 `package.json` 上，整条 bundle 就加载失败。

**修法**：

- **只有 `.ps1` 补 BOM**；`.json` / `.yml` / `.js` 一律存 **UTF-8 无 BOM**
- 编辑完 `.ps1` 补 BOM、编辑完 `.json` 确认首字节是 `7B`（`{`）而不是 `EF BB BF`
- 插件加载失败时先看 diagnostic 字段，不要只看界面「异常」
---

## 18. 凭记忆报数字，报出来的是「旧实话」

**现象**：一直跟人说「核心层 1893 字节」，实际早就是 2035。数字是真的报过，只是那时是真的。

**根因**：记忆里存的是「当时写下的值」，参数、文件大小、条目数都会变。凭记忆出口，等于把旧快照当现状。

**为什么难发现**：谎话会被质疑，旧实话不会 —— 因为它是你自己说的，你信它，别人也无从核对。

**修法**：

- **说之前先查**，只针对三类：数字（字节/条数/金额）、日期（今天几号/几天后）、路径（文件在哪）
- 查不到就先标「凭记忆」，别把它说成事实
- 把这类值做成引脚（见 `scripts/pin.ps1`）：记着值 vs 现场算的值一比，漂了立刻知道
---

## 19. 幻觉的形态是「伪造来源」，不是「算错」

**现象**：给一个数，还写着「来自用户说的」——但用户从没说过这个数。

**根因**：查会话日志发现推理原文是 `40 元, 20 days → 2 元/天 … That's from user's statements (40块)`。用户只给了「40 元」，**「20 天」是模型自己造的，却被挂上了用户作为来源**。来源一假，所有依赖来源的判据（可追溯、以记忆为准）全部失效。

**修法**：

- 归因必须有引文：凡写「用户说 / 他说过 / 原话」，同一句必须带引号原话或标明来源，否则删掉归因改成「推断」
- 上脚本强制：`scripts/attrib.ps1` 扫所有 md，归因无引文就报；接进 `verify.ps1`
- 更严的做法（未普遍实现）：证据必须是**可复现指针**（文件+行号 / 命令+输出 / 日志+帧号），并能在事后重放

## 20. 写入端与检查端格式不一致，检查就是假绿

**现象**：检查脚本报「没有畸形行」，但实际有一行是「两条记录并成一行、第二条缺年份」。

**根因**：①检查正则只看行首（`^- \[` 之后是完整日期就放过），行内合并看不出来；②写入端 `stamp()` 写 `MM-dd HH:mm`，检查端要求 `yyyy-MM-dd HH:mm`——**两端各写各的，没人对账**。

**修法**：

- 检查要查「整行」，不是只查行首；加一条「一行出现两个时间戳」的判据
- 写入端和检查端用同一格式，改一处必须同步另一处（脚本 + 插件）
- 历史数据一次性归一（补年份），归一后立刻重跑检查

## 21. 多帧 zstd 的日志，解一次只拿到第一帧

**现象**：6.9 MB 的 `session.v4.jsonl.zstd` 解压后只有 252 字节（一条 session 头）。

**根因**：日志是**追加式多帧**的 zstd；`zstdDecompressSync` / `createZstdDecompress` 只解第一帧就停。

**修法**：按 zstd 魔数 `28 B5 2F FD` 切帧，逐帧解压再拼接：

```js
const magic=[0x28,0xB5,0x2F,0xFD]; // 扫出所有帧起点，逐段 zstdDecompressSync
```

实测该文件 5853 帧，全部解压后 16.8 MB——**这是能定位「当时到底怎么想的」的唯一办法**。

## 22. 一条判据写进核心层，不等于行为会改

**现象**：「参数与变量不许只差大小写」写进核心层之后，同一个错又犯了一次（`$Keep` / `$keep`）。

**根因**：写进必读页只保证「下次会读到」，不保证「写的时候想起来」。记忆解决不了注意力。

**修法**：把「记不住」换成人机检查——`scripts/lint.ps1` 静态扫参数与局部变量同名、PS 5.1 不支持的语法（`??` / `-LeafBase`）。**能自动查的别指望自觉。**

## 23. PowerShell 变量同名会静默覆盖（五次）

**现象**：给 `verify.ps1` 加新检查，用了 `$rows` 存台账行——而 `$rows` 在文件里是**结果数组**。跑完 26 项只剩 6 项输出，**没有任何报错**。

**根因**：PowerShell 变量不分大小写、不分区作用域。同名即覆盖，且覆盖后语法完全合法。

**修法**：

- 局部变量一律带前缀（`$ledgerRows`），起名前扫一遍整个文件
- 静态检查：`lint.ps1` 报「脚本级与块内都赋值」的变量；先当提示跑（首版 18 处、多为正常累加器），把 `+=` 排除后剩 4 处
- **判据：只看「没报错」不算过——这次没报错，只是少了 24 项。改完必须跑完整输出并数项数。**

## 24. PS 5.1 不支持三元运算符，而且它会静默让整条命令不执行

**现象**：一行 `($x) ? 'a' : 'b'` 让整条 PowerShell 命令报 ParserError，**前面所有的文件修改一个字都没执行**——但如果你只看后面的输出，会以为改过了。

**根因**：`? :` 是 PowerShell 7 的语法。5.1 连同 `??`、`-LeafBase` 一起不支持。

**修法**：

- `lint.ps1` 加窄正则检测 `? 字面量/变量 :`（避免误伤 URL 与问号句）
- **改动类命令与验证类命令分开跑**：改完立刻单独跑一次读取，确认改动真的落盘
