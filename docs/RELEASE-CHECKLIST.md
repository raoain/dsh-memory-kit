# 发布前自检清单 / Release Checklist

> 用途：每次发论文、发版本、改动仓库前，逐条过一遍。每一条都来自一次真实的翻车。
> Purpose: run through this before every release. Every line comes from a real failure.

## 一、归属与切分 / Attribution and slicing

- [ ] **同一段原话不同时挂在两篇下**。母本按篇切片，切片文件头写清「第 N 段 → 第 X 篇」。
- [ ] **附件属于本篇，不是别篇**。不看文件名，看内容来源：第三篇的母本不能挂到第四篇。
- [ ] 切片里的每一段，都能指出它在论文正文的哪一节被用（不用就删）。

## 二、DOI 与版本 / DOIs and versions

- [ ] 对外入口一律用 **概念 DOI**（`conceptdoi` 字段），不是 v1 的版本 DOI。
- [ ] 验证法：`curl -sL https://doi.org/<doi>` 看最终落到哪个 `/records/<id>`，与页面上 Version 对上。
- [ ] 版本 DOI 只在「引用某一版原文」时出现。
- [ ] README 的入口表与 DOI 表一致；新旧版本不并存于同一入口。

## 三、摘要与正文 / Abstract and body

- [ ] 摘要**先列清单**（本篇讲哪几件事），正文逐节给细节与判据，讨论给可推翻条件。
- [ ] 摘要里**不塞做法细节**——塞了就是重复（正文会再讲一遍）。
- [ ] 中英摘要一一对应；英文不新增中文没有的主张。
- [ ] 每节标题「中文 / English」，段落中英对照。

## 四、内容覆盖 / Coverage

- [ ] 拿 `11-结论.md` 的 S / F 系列逐条核：哪些属于本篇却还没写？
- [ ] 原话段落一字不改；只做分段、断句补标点、改错别字。
- [ ] 不新增词、不改句式；器官可借，思路必须重推。
- [ ] 每条主张能回答「什么能推翻它」。

## 五、文件与内容一致性 / Files match content

- [ ] PDF 是从**当前 md** 生成的（生成后核对 md 的修改时间早于 PDF）。
- [ ] 抽检：从 PDF 提取文本，搜本篇新增的关键词，必须命中（防止发了旧 PDF）。
- [ ] Zenodo 记录的文件列表 = 本地文件列表；没有多挂、漏挂。
- [ ] 下载链接可访问（HTTP 200）。

## 六、发布闸门 / Release gate

- [ ] **发布 = 四类闸门之一（发布 / 删除 / 密钥 / 花钱），必须经用户明确点头。**
- [ ] 用户说「1」或「都写好了为什么不发」可以算授权；用户没说到发，就不发。
- [ ] 发之前把文件给用户看（路径 + 关键改动），等回复。
