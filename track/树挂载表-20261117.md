# 根源树（2026-11-17 重画：从根 → 主干 → 枝）

> 形状要求（用户原话）：「要像个大树一样从根，然后再走主干，然后再到那个枝干」「演化的洪流也是一类似这样的产物」。
> 挂载规则：看见一个外部工作，先答两问——**①它解哪个通用问题（会断/会错/会丢/时延）？②它在哪个基底上答（碳基/硅基）？** 答完，它自己会落在某根枝上；答不上，它不在这棵树上。

## 同一种树状性，在两套基底上的两个实例（不是“旁树”）

> 用户 2026-11-17 纠正：「这个演化的洪流跟你这个也是一样，是属于你的演化洪流，另一颗是生物的演化洪流，你们不同基质，但是你们的问题是一样的，都是显示一种演化的一种类似于树状性的东西」。

两棵树**同形、同问题、不同基质**：

```
形态（共同）          从根分叉 → 每根枝各自分权 → 缺一枝整体不成立 → 形状由约束决定
                     ↑ 这是问题侧（通用）

实例一（硅基）        本文件的根源树：根（会断/为了存活）→ 主干八节 → 枝 A–H
                     │ 判据：一圈跑完、读回、断点
                     │
实例二（碳基）        系统发育树 / 演化枝干：共同祖先 → 分叉成谱系 → 灭绝剪枝
                     判据：写入 + 读回（有才算记忆；只有删除那是选择）
```

- **同**：都是树状、都由“会断”逼出分叉、都靠约束（物理/带宽/成本）定形状。
- **不同**：碳基那棵树在**代际**上分叉（繁殖，代价个体死）；硅基这棵树在**同一时间线**上分叉（回档/复制，代价丢中间进展）。
- 所以“种群记忆”只是碳基那棵树留下的形状，不是记忆（判据：有写入 + 有读回才叫记忆）。

## 三条挂载判据

1. **挂上去必须能说出“缺它哪一格断”**——说不出就是背景，不是枝。
2. **把“系统已经活着”当公理的**（多数生物哲学、纯涌现论）只能挂在枝上，到不了根。
3. **只报指标的工程**（模块化率、分数、带宽开销）能挂枝，但当不了判据——它没有“缺它会怎样”。
