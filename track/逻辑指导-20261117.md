# 逻辑指导（2026-11-17）——把一句话推成一条链的操作规程

> 用途：下次要判断任何说法（我们的、他们的、我自己的），按这五步走。每一步都能被外部检查，缺一步就不许给结论。

## 一、五步（顺序不许换）

1. **先找前件**：这句话要成立，必须先有什么？（写出来，一句话）
   - 例：「必须维持」的前件是「会断」。
2. **写所以然**：从前件到结论中间那一步，凭什么成立？
   - 例：会断 → 所以「继续」不是选项，是条件。
3. **写接口断言**：这一步的结论，能不能当下一步的前件？
   - 例：「维持」→「一圈一圈接下去」；接口写不出，就是两段拼不上。
4. **挂推翻点**：这一步错了会怎样？
   - 例：若存在「不必维持也不会断却照样长大」的载体，第 1 步就错。
5. **报三段式**：①结论一句 ②依据（可核） ③真分歧才写分歧+理由。
   - **转折必须带新事实 / 真分歧 / 可推翻点**，否则删掉。

## 二、三条通用判据

- **没有推翻点 = 描述**（不是推导）。
- **接口写不出 = 两篇论文**（不是一次解答）。
- **只在文字里成立、跑起来就散 = 还没被工程纠正过**（先跑，再信）。

## 三、看外部工作时只用两问（挂树法）

1. 它解的是哪个通用问题？（会断 / 会错 / 会丢 / 时延）
2. 它在哪个基底上答？（碳基 / 硅基）

两问答完，它自己会落到树上某根枝；答不出，就别写进对照表。

## 四、常见跑偏（我犯过的，写在这里当镜子）

| 跑偏 | 症状 | 纠正 |
|---|---|---|
| 好话说一半再转折 | “对……不过准确说法是……” | 转折后无新事实就删 |
| 空转 | 一直做能打勾的内务 | 换完成标准：能被总线证明的判据 |
| 抢优先级 | 先读原始输入再写给环看 | 输入先落环的账，再被我看见 |
| 把识别当修复 | 归档、命名、贴标签就算处理完 | 要么修根因，要么让它变成会痛的 FAIL |
| 拿抽样冒充世界 | 用“覆盖广”代替“可回指” | 问第一条记录来自哪个个体 |

## 五、一句话

**结论谁都会给；能从第 1 步推到第 5 步、且每步都挂着推翻点的，才叫推导。**
