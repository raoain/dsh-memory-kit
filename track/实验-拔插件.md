## 实际执行记录（2026-10-29 02:50 补）

### 开工时看到的现场（不是计划，是查到的）

- `~\.dsh\profiles\desktop\cordis.patch.yml` 里 meow-memory 已是 `disabled: true`，文件写入时间 02:41:58
- 同目录 `package.json` 写入时间 02:48:44（meow-memory 仍在 dependencies，bundles 列表本来就不含它）
- 本次会话工具清单里**没有任何 memory_\* 工具**，只有 notebook_\*（dsh-notebook 仍启用）
- 记忆库没丢：`.dsh-meow\memory.db` 208 KB（verify 报的是库大小，不是条数）
- 与 00:00 的 yml 备份逐行比对：**唯一差异就是 `disabled: true/false`**，所以恢复只需把这一行改回 false（或 `meow-toggle.ps1 -On`）

### 检查结果

- `wake.ps1` 已跑（读过核心层 1794 B + 本机错题本 2017 B）
- `verify.ps1` 21 项 OK / 0 WARN / 0 FAIL
- `pin.ps1 -Diff` 起初报 2 项漂移（cfg.patch / cfg.pkg）—— 就是上面那次关插件造成的，不是故障；已 `-Init` 重钉（43 项全对齐）

> 注意：现在钉的是「插件已拔」的状态。恢复插件后 cfg.patch / cfg.pkg 会再漂一次，**那是预期的**，恢复完再 `-Init` 一次就好。

### 一个顺序问题（计划书写错了，已在此更正）

计划书把「关插件」写在「重启前问一轮」之前。但 `plugin_manager set_plugin` 是当场生效的，先关再问，第一轮就已经是拔掉之后的状态，没有对照组。正确顺序应是：备份 → 钉住 → **先问第一轮（插件还在）** → 关插件 → 重启 → 问第二轮。

本次现场已经是拔掉之后，第一轮是否有记录只有船长手里知道。**我不去会话日志里翻** —— 翻到题目就等于作弊，这一页自己写了「连题目都是提示」。
