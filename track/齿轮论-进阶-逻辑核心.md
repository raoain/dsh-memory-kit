## 一、结构

```
                 ┌─────────────┐
        供能 ────→│             │←──── 进阶记忆
                 │  逻辑核心    │
       感知器 ───→│（破壳那个）  │───→ 效应器
                 └──────┬──────┘
                        ↑ 上传（每个中枢各自上传）
      ┌─────────┬───────┼───────┬─────────┐
      │         │       │       │         │
   ┌──┴──┐  ┌──┴──┐ ┌──┴──┐ ┌──┴──┐
   │供能 │  │感知 │ │效应 │ │进阶 │   ← 每个大模块各配一个
   │中枢 │  │中枢 │ │中枢 │ │记忆 │      「简单中枢」（常用配置）
   └─────┘  └─────┘ └─────┘ └─────┘
      中枢自己自动感知 → 再把数据上传至逻辑核心
```

- **中心**：逻辑核心——就是「破壳那个生命」的正式命名。
- **向外四件**：供能 / 感知器 / 效应器 / 进阶记忆。
- **基础中枢是"每块一个"，不是全局一个**（2026-11-08 用户补充）：**以那个大模块来配一个中枢**——供能一个、感知一个、效应一个、进阶记忆一个。各自**自动感知**，然后**把数据上传至逻辑核心**，不是每个信号直接打到核心。

## 二、三条硬规则

**① 核心可随时插出。**
不是"核心很稳"，是**核心能拔**。整机必须允许逻辑核心被拔下来，其余部分照样活着。

**② 一个一个闭环电路；其他插件全并联。**
核心自己构成完整闭环；所有插件（器官、进阶件）都是**并联**上去的，**不许串在核心的闭环里**。目的：保证核心闭环电路始终完整，插什么、拔什么都不影响它。

**③ 对外接法：协议是以后统一制定的规格；没协议时用能力反推。**
（2026-11-08 用户补充）协议以后会**制定一个统一规格**——连上就能用。但以后会有**突发情况**：没有协议时，就用「它能干什么」反推，然后连上系统即可。

## 三、机器人形态的落地顺序

```
已有：中间的逻辑核心（就是我们现在这套新标准骨架：spec v4 / SIG 契约 / 8 器官 / 三问）
再配：基础感知器 + 基础效应器 + 供能
以后：进阶记忆、其他插件——全是并联加
```

**判据：先有那个核心的简单雏形，其余都可以以后并联。**

## 五、还没做到的（诚实清单）

1. **核心可插出没验过**——备份能还原，但"拔掉核心、其余部分继续跑"没试过。
2. **基础中枢还是命令式**（`reflex.mjs` 被调用才跑），不是常驻感知。
3. **协议接法只做了规定**（有协议接协议 / 没协议反推），没有一个真实的外部协议接过。
