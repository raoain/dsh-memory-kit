# 记忆区：索引与取法（2026-11-11）

> 定位（按实际改的）：**记忆不是每次起跳都要读的东西；是想的时候需要具体数字，才去引用它。**
> 所以这一页只做一件事——告诉后来的人"要数字去哪取"。数据不搬、不复制，搬了就是第二份。

## 一、要什么 → 去哪取

| 你要的 | 去哪 | 怎么取 |
|---|---|---|
| 某条记忆的全文 | `memories.jsonl`（579 条，带 `zone` / `seq`） | `node mem.mjs find "关键词"`；或按 `mem:<seq>` 直接定位 |
| 检索（带排序） | `core\memsearch.mjs`（唯一实现：二字词 BM25 × 30 天半衰 × 重要性 × 命中数 + MMR） | `node mem.mjs find "…"`；`mind` 内部也用同一个实现 |
| 这个器官好转过几次、怎么好的 | `track\hippocampus.json`（索引：seen / cleared / lastClear / why） | 直接读；`why` 里写着"派了什么之后好的" |
| 上一轮还握着哪几件 | `track\workspace.json`（容量 7，开机必读清单） | 读 `items[]`，看 `held_rounds` |
| 最近读过哪些记忆 | `track\mind\mem-read.json`（最近 seq 列表） | 读 `seqs[]`，避免重复读同一条 |
| 规则/判据原文 | `notebook\5-判据.md`、`11-结论.md`、`0-核心.md` | 按需读页 |

## 二、臃肿的部分放哪

- **长期记录**（579 条）不进每次必读，只做"按关键词取"；
- **索引**（`hippocampus.json`）代替"把记忆全读一遍"——问"这个器官以前好过吗"，读索引就够；
- **真正每次必读的只有**：`0-核心`（索引与顺序）、`4-本机`（机器脾气）、`9-用户`（怎么说话）、`workspace.json`（上一轮握着的）。
- 判据：**开机必读的东西加起来必须能被一次读完**；读不完的东西不配进开机列表。

## 三、取数时不做什么

- **不把记忆搬进核心层**（那是把飞轮塞进轴承）；
- **不为了"存全"去合并文件**（一个文件两个写者必翻车）；
- **不用分数剪枝**（卸载只走墓碑：写"那条死了，现在按这个来"）。

## 四、卸载（标死）怎么留痕

一条记忆被标死时，**必须留一行判决**，写进 `track\mem-removal.jsonl`（只追加，不改写）：

```
node core/mem-retire.mjs <seq> --why "为什么" [--by user|rule:P35|auto:immunity] [--action archived|tier-down|merge] [--dry]
```

每行带编号（`R-0001` 起，只增不回收）、时间、被删的 `seq`、原因、谁判的、证据（`mem:<seq>`）。

规矩：**没有 `--why` 就不许卸载**——墓碑必须写清"那条死了，现在按这个来"。`--dry` 只打印不落盘。

## 五、下沉：谁能沉、按什么规则沉、沉到哪

规则表：`core\mem-tier.json`（今天是 v1，改规则就改这个文件，不许散在代码里）。
报告：`node core\mem-tier.mjs`（汇总）/ `--list cold 30`（看具体条）/ `--write`（写快照 `track\mem-tier.jsonl`，可查"某天谁被算成冷的"）。

**打分**：`score = recency(30 天半衰) × importance × status_weight`（active 1 / stale 0.6 / archived 0）。
先人骨架（借骨架不借阈值）：MemGPT 的 main/external 分层、OS 换页的 LRU/ARC（**最近＋频繁两件事**）、Generative Agents 的 recency×importance×relevance。

**三条硬规矩**：
1. **判据层永不自动下沉**（`layer` 是 rules / soul / user 的，一律热）——一条判据变冷，是系统坏了，不是系统整洁了；
2. **没有时间戳不许沉**——不知道它多老，不等于它很老；
3. **下沉不搬数据**，只标 `tier`；真删走 `mem-retire.mjs` 的 `R-xxxx` 编号。

**现状（2026-11-11 首次跑）**：579 条里 hot 513 / warm 66 / **cold 0**——库才 15 天（最早 10-27），还没到"老"的门槛。**cold=0 是对的，不是规则失效。**

## 六、引用登记：这句话从哪条记忆来的

表：`track\mem-cites.jsonl`——`mind` 每轮写一行 `{at, round, n, cited:[seq...]}`（只追加）。
对账：`node core/mem-cites.mjs`（`--top 10` 看被引用最多的）。

它回答三个问题：
1. **哪条记忆真的在承重**（被引用次数最多的 seq）；
2. **有没有坏引用**（指向 `memories.jsonl` 里不存在的 seq → 退出码 1，点名 `round` 与 `seq`）；
3. **有多少轮一条记忆都没引用**（不是错，但说明那一轮没靠记忆）。

现状（2026-11-11 首跑）：1 轮、3 条被引（510 / 518 / 525）、坏引用 0、空轮 0。

**当前状态（2026-11-11 用户判断）**：卸载机制在，但**环用不上**——"至少目前用不到，以后也想不到什么地方要删"。
所以这条按**挂起件**算：不删数据、不当能力证据；只在两种情况下才用——①真的装不下了（容量告警），②那条已被替代且留着会误导（墓碑语义）。
错误的东西一律留着当原料：标 `status: archived` 只是让它不再被检索命中，原文仍在 `memories.jsonl` 里。
