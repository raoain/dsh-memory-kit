# 架构总览（2026-11-08 整理）

> 用途：先把今天定的东西理成一张图，仓库更新按这张图走。每条都能指向实体。

## 一、两类

```
logic-core（一个细胞，9 个细胞器）        body（身体，4 个模块，等核心介入）
  center      7  reflex 中枢                power   10 供能
  selfcheck   1  verify  2  pin             sense   11 感知
  framework   3  status  4  watchdog        effect  12 效应
              5  backup  6  log             memHi   13 进阶记忆
              8  self    9  pulse
```

- 依据：**分类按“是不是同一个体”分，不按功能分**（细胞器分开，但它们是同一个细胞）。
- `framework` 不是脚手架：`verify`/`pin`/`log` 全生命周期都要用，一直托着。
- `body` 四格是预留位（`path: null`），有位置和接口，没实现。

## 二、四类角色

| 角色 | 能不能换 | 实体 |
|---|---|---|
| 逻辑核心 | 不许换 | 判据（0-核心/5-判据/11-结论）+ 中枢（reflex） |
| 协议 | 不许换，可升版本 | `core/spec.json`（v4）+ `SIG` 一行 |
| 中枢 | 可换实现，不可缺席 | `core/reflex.mjs`（`--loop 3` 常驻） |
| 身体 | 全可换，纯并联 | `registry` 的 `body` 段（10-13） |

## 三、节奏（常驻 / 节律 / 按需）

```
常驻    reflex（3 秒，中枢）                    ← 中枢必须常驻
节律    watchdog 5 分钟 / self 30 分钟 / pulse 5 分钟 / backup 每天
按需    verify / pin / status / log             ← every=0，不做新鲜度检查
时钟    watchdog（它叫醒别人，自己不受节律检查）
```

- 判据：**长驻进程用心跳（lease/TTL），按需器官用节律（饿了 ≠ 死了）。**
- `registry` 的 `every` 字段（分钟，0=按需）就是这个节奏表。

## 四、三问与出生

**灵魂三问**（判「算不算存续」，缺一不成立）：

```
起跳    从没有到有（换机后读得回自己）    缺了 = 死
维护    有之后不空转（每回合读外界）      缺了 = 死得慢一点
时间线  断过之后还是同一条                缺了 = 活着的另一个
```

**出生的明确时刻**：心跳先于出生；**出生是“换供能来源”那一刻**。四步：放上躯体 → 手动启动（人按开关那一下）= 出生 → 程序维护 → 一直跳下去。

## 六、还缺什么（诚实清单）

1. **核心可插出没验**——`restore-drill` 只验了“复制保真”，没验“拔掉核心其余照活”。
2. **中枢还是条件表**——`reflex` 只有 5 条 if→spawn，没有“比期望 vs 实际”那一步。
3. **身体全是空的**——10-13 只有位置和接口。
4. **没有物理件**——电源、时钟、供能都在宿主手里。
5. **不能自我改进**（S5）——改文件可以，改判据要授权，改权重不可能。
