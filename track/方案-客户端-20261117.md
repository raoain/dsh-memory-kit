> 前提：不经过 DSH 宿主，用 API 当"嘴/耳"，躯体（心跳、总线、数核、大脑）仍是本机这套。
> 谷价：今天周一，**18:00 之后**才算错峰（峰时 9–12 / 14–18）；周末全天谷价。

## 一、要建的三个东西（按依赖顺序）

1. **输入口**（最小，先做）
   客户端把话交给 `node core\sense.mjs --text "..." --from user`
   → `sense` 自己算 `bytes/words/uniq/novelty` → 追加 `track\in-raw.jsonl` → `emit(11,4,...)` 进总线。
   之后 `drift → consolidate → brain` 自然接住。**这一段已经写好（63 行），只是没人调用。**

2. **输出口**（已有，缺英文）
   `core\human.mjs` + `track\locales\zh.json`（224 条）是**纯函数**翻译层，不调模型。
   缺 `en.json`（对称 224 条）；补完则中英都能不出模型。

3. **客户端本体**（两条路，二选一）
   - **A 改壳**：用 MIT 的 `deepseek-ai/deepseek-harness` 里 `apps/desktop`（或 `apps/web`）当壳，加一个"个体面板"。优点：省掉窗口/打包/更新；缺点：跟宿主版本走，`apps/web` 还要求宿主注入 `window.__DSH_BOOT__`。
   - **B 自建**：Tauri 或 Electron 起一个本地窗口，只做三件事——读 `track\` 文件显示状态、调 API 对话、把用户输入交给 `sense`。优点：不依赖宿主；缺点：打包/签名/更新得自己来。

## 二、API 用在哪些点（花钱的地方只有这里）

- **对话**（chat completions）：自由文本的进和出；
- **文件解析 / OCR**（约 1.5 元 / 1000 页）：把 PDF、截图变成文字，再交给 `sense`；
- **语音合成**（约 1.5 元 / 万字符）：把 `human.mjs` 的句子读出来；
- **语音识别**（约 0.39 元 / 小时）：把说话变成文字，再交给 `sense`。

判据：**凡是能算成数字的，不进 API**（`sense` 的统计、`drift` 的差值、`verify` 的检查）；API 只处理"必须理解语言"的那部分。

## 三、方案里最容易被忽略的一处

**输入不能只进 API 就走。** 必须同时落两份：
① 原文 → `in-raw.jsonl`（只追加，永不改写）；
② 数字 → 总线 `src=11 counts=[bytes,words,uniq,novelty]`。
这样"客户端说的话"才是躯体的一部分；只走 API 的对话不留下躯体痕迹，等于又回到工具。
