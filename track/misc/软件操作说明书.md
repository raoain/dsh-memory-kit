# 软件操作说明书（2026-11-22 建）

> **为什么有这一本**：用户的话——「你对于一个个软件保留个记录，它的操作方式不就好了吗？以前不是已经让你写过那个操作的那个说明书了吗？在一个软件之前放一本。」
> 意思：**别靠记规矩**（BOM 该不该有、数据在哪、红了怎么查），**每个软件前面放一本，出问题查它**。
> 用法：某个软件出状况，先翻它那一节；改完这一节要跟着改（否则说明书就成了新的假依据）。

---

## 一、meow-memory（记忆库，0.32.1）

| 项 | 值 |
|---|---|
| 装在哪 | profile `desktop` 依赖，`~\.dsh\profiles\desktop\node_modules\meow-memory` |
| **数据在哪** | **`<工作区>\.dsh-meow\memory.db`**（+`-wal` / `-shm`）；工作区＝`C:\Users\Administrator\Documents\deepseek-harness\default-workspace` |
| 配置/日志在哪 | `C:\Users\Administrator\.dsh-meow\`（`perf.log`、`settings-diag.log`、`window-index.json`、`migrate-v0-state.json`） |
| 怎么用 | 工具 `memory_remember` / `memory_search` / `memory_project` / `memory_read` / `memory_update`；会话开头自动注入快照 |
| 本体里的副本 | `memories.jsonl`（可读快照）＋ `track\misc\plugin-data\meow\`（二进制副本，`plugin-sync.ps1` 每次收工回拉） |
| 常见故障 | ①GUI 报 `HMR transactions cannot be nested`＝热更新在事务里再开事务（2026-11-13 出现过 4 次），不是数据坏了；②库文件被占用：先确认没有别的会话在写（单写者） |
| 判据 | 库的两处必须分清：**家目录那份是配置/日志，工作区那份才是库本体** |

## 二、@local/core-gate（门闸，1.0.0，link）

| 项 | 值 |
|---|---|
| 装在哪 | `F:\Tools\core-gate`（profile 里 `link:` 引用） |
| 干什么 | 本回合**零外部读取**却要接着写时，拦下该步（可切观察/拦截）；就是每条消息顶上那条【门闸】提示 |
| 数据/配置 | 无独立数据；配置在 `cordis.patch.yml` 与插件配置层 |
| 文件清单 | `index.js` / `package.json` / `cordis.patch.yml` / `icon.svg` / `locale\{en,zh}.json` |
| **常见故障** | GUI 变红、提示「**包元信息错误**……`is not valid JSON`」→ **`locale\*.json` 带了 UTF-8 BOM**（首 3 字节 `EF BB BF`）。**修法**：去 BOM（写成无 BOM 的 UTF-8）→ **重载/刷新** 才变绿 |
| 它怎么读 locale | **不是它自己读**：宿主按 `package.json` 的 `exports["./locale/*.json"]` 读并 `JSON.parse`。所以这是**串联链**：宿主 → exports → 文件 → JSON.parse，一段错全断（见 `5-判据.md` P43） |
| 判据 | `.ps1` 要 **1 个** BOM；`.json` 要 **0 个** BOM。方向相反，别记反——直接看文件头 3 字节 |

## 三、@local/noread-guard（下限闸，1.0.0，link）

| 项 | 值 |
|---|---|

| 干什么 | 本回合零外部读取却要接着写时，**把输出压成一句**（比 core-gate 更软：不拦，只缩短） |

## 七、coo-day1 本体（47 个脚本）

| 项 | 值 |
|---|---|
| 干什么 | 心跳/总线/账本/收工链；`start.ps1` 开工、`close.ps1` 收工 |
| 收工链 | 检查 → 便签 → log → 复查 → 双盘备份 → 5b 区册 → 5c 总纲 → **5d 插件同步** |
| 路径约定 | 脚本不写死 track 路径，统一走 `core\paths.json`（`Get-CooPath` / `trackPath`） |
| 常见故障 | ①`verify` 红＝看是第几项，`.json`/BOM/留痕比是常客；②`pin` 漂移＝预期内就别动（等它不行再补） |
| 判据 | **能查的不许猜**；改 `.ps1` 走「备份 → edit → fix-bom → ParseFile → 跑一次 → lint/verify → log」 |

## 附：这本说明书自己怎么维护

- **每加一个软件，加一节**；每修一次故障，把"常见故障"那一行写实（写"怎么查"而不是"为什么"）。
- 找不到某一节 → 说明这个软件是**新装的**，先补节再谈别的。
- 判据：**说明书里没有的软件，等于没被接进本体**（悬空）。
