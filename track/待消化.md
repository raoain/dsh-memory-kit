# 待消化 · 暂存区（staging）

> **为什么要有这一页**：档案里现在混着两种东西——「刚撞的（没消化）」和「消化过的（有根因有修法）」。
> 混在一起，查档案时读到的一半是生料。所以先入库到这一页，反刍完才进 2-档案 / 5-判据 / 6-话。
>
> 借自 `agents-memory` 的 staging → distill：先抽到暂存区，再人工/agent 消化成类型化事实。

---

## 一、什么进这里（四类）

```
① 刚撞的坑（还说不清根因）        → 反刍后进 2-档案
② 没验证的想法（像「五链」「反刍」） → 反刍后进 5-判据 或 10-链
③ 听来的同类（视频/文章/仓库）      → 反刍后进 2-档案（外部同类）或直接删
④ 未定的决定（等对方点头或等数据）  → 反刍后做决定，或标「等什么」
```

**不进这里的**：能直接写进档案的（有根因+修法）、能直接做检查器的、一次性的流水（那些进 `1-工作.md`）。

## 二、反刍规则（防空转）

```
· 每次反刍只处理 3 条以内（多了就是走过场）
· 同一条最多嚼两次；第三次必须做决定：归档 / 降级 / 删
· 每次咀嚼必须产出「新东西」：一条判据、一个检查器、一次实测、或一个明确的「没用」
· 超过 7 天没动的 → 视为「冷」，下次反刍优先清掉或删
```

**判据**：反刍完这条还在原处、且没有任何产物 → 那不是没来得及，是它没用。

## 三、格式（一行一条，登记时写）

```
- [YYYY-MM-DD] 素材一句话 | 来源（哪个会话/哪个文件/哪条视频） | 嚼过几次 | 现在卡在哪
```

**「现在卡在哪」必须写具体**（缺哪个数据、等谁点头、需要哪次实测），否则它一定会烂在这里。

## 五、在待消化期间，不许把它当结论用

> 借自 IETF HEM 的挂起态：等待期间禁止任何状态转移。我们的暂存区原先只规定了「放哪」，没规定「等的时候能拿它干什么」。

```
① 未反刍的条目，不许拿去当论据（写文章、下判断、改判据都不行）
② 要引用，必须先反刍一次，把它变成「档案条目 / 判据 / 明确的没用」
③ 反刍完仍不确定的，就明写「仍未定，卡在 X」，不许含糊地当结论
```

**为什么**：暂存区里最容易被误用的，是那些「看起来已经有结论」的条目——它们还带着兴奋，但没经过任何检验。**兴奋不是证据。**

## 「要不要写进 X」这个句式（2026-11-08，抓不到，只能换写法）

- **事实**：`~/.dsh/AGENTS.md` 第 13 条早写着「必跑的不问……不许问『要不要』」，我今天还是问了两次（「要写进 5-判据 吗」「要现在挂吗」）。
- **为什么抓不到**：这句话出现在对话层，不在任何文件里；verify/pin/log 扫的都是文件，所以没有检查项能抓它。
- **能做的只有换句式**：想说「要不要 X？」的时候，改成「X 我现在做，做完报」。**不是提醒自己别问，是让那个问句没有地方出现。**
- **为什么只进这里**：它没有文件消费者（不改变任何脚本/检查/页面），按「新发现必须有消费者」只能放待消化。
- 待定：如果这条再犯三次以上，考虑让 `log.ps1 -Text` 拒收含「要不要」的条目——但那只能抓"我写进文件的"，抓不到"我说出口的"。
