# 接缝 · 链与链之间的十个交接点

> 为什么单开一页：**幻觉不在链内部，在链的接缝里。**
> 论文 *Hallucination Snowball*（arXiv 2608.14588）量化过：边界处验证能把幻觉存活率从 58.4% 压到 16.2%，而只做末端检查只改善 2.3 个百分点。
> **"When you verify matters more than whether you verify."**

五条链（见 `10-链.md`）：表达 E / 验证 V / 执行 X / 记忆 M / 学习 L。

## 先说清：我们的接缝和别人不是同一类

外来研究（如 *Hallucination Snowball*）的边界是**数据在多 agent 之间交接**。我们的不一样，因为差异从更前面就开始了：

```
他们：规则在提示词里，边界落在「数据交接」
我们：规则写成文件、还要求可检查，边界落在「指令 → 动作」
```

所以接缝分三类，主战场是第②类：

| 类 | 内容 | 我们的例子 |
|---|---|---|
| ① 数据交接 | 两个执行者之间传数据 | 基本没有（单 agent） |
| ② 指令→动作 | 文件里写了，动手时没照做 | E→V（写了验证链，写稿时没过）、M→X（写了规则，动手时没读）、V→L（验出错，没变成机制） |
| ③ 动作→记录 | 做了，没留痕 | X→M（改了没记） |

**换句话说：我们的接缝，本质是「哑炮」的同义词** —— 规则存在，但触发时没人读。

**所以别人的量化数字（89.3% 逃逸之类）只能当方向参考，不能当证据**：他们量的是数据传递损失，我们量的是「指令被执行的比例」，两件事。

## 十个接缝

| # | 接缝 | 交接的是什么 | 现在靠什么衔接 | 最脆的地方 | 怎么查 |
|---|---|---|---|---|---|
| 1 | **E→V** | 我要说出口的事实断言 | 无（全凭自觉） | **写作时数字查了，引用/因果没验** | 每拿到一个数/引用，当场过 V1–V5，再落笔 |
| 2 | **V→E** | 放行后的话 | `证:` 尾缀 | 放行了但表述夸大 | 写完回读一遍：数字对上了，因果有没有被讲歪 |
| 3 | **E→X** | 「我要改这个东西」 | 三行前置 | 想改但没写三行就开始 | 破坏性动作前必须贴三行，没有就不许动 |
| 4 | **X→V** | 改完的东西 | verify / pin / probe | 改完没跑，或跑了没看 FAIL | 改完立刻跑三项；FAIL 就不许说完成 |
| 5 | **X→M** | 改动要不要记 | 工作层 `证:` | 改了但没记，下次重复踩 | 改动必记一条，带 `证:` |
| 6 | **M→X** | 记下的规则在动手时被触发 | 无 | **哑炮**：规则在文件里，动手时没人读 | 探针 / 引脚 / 引脚漂移报警 |
| 7 | **M→V** | 记忆里的断言 vs 现在的真值 | `pin -Diff` | 数字变了但记忆没更新 | 引脚对账；漂移就重钉或改记忆 |
| 8 | **V→M** | 验出的错要不要变成机制 | 判据 / 检查器 | 只记了档案，行为没改 | 同根因第二次必须升级成检查器 |
| 9 | **L→M** | 撞坑后写进哪 | 档案 / 判据 / 待消化 | 写进档案就以为学到了 | 见第 8 条：不进检查器不算学 |
| 10 | **V→L** | 检验结果要不要触发学习 | 无 | **验出错了，没人据此改进** | 每次 FAIL 必须产出一条「下一步动作」 |

## 目前最脆的三个（2026-10-29 判断）

```
① E→V  写作时的事实断言完全没有门（今晚文章里引用格式错，是事后 attrib 抓的）
② M→X  记下的规则在动手时不被触发（lint 的参数检查死了 21 小时，就是这类）
③ V→L  验出错之后，没有强制把错变成机制（只写档案 = 没学）
```

## 判据：接缝算不算接上了

```
拔掉接缝处的那个东西，下游会不会立刻报出来？
  会 → 接上了
  不会 → 那是哑炮，不是接缝
```

## 和「链条」的关系

```
链内：靠齿序保证顺序（V1→V5）
接缝：靠「外部动作」保证交接（打开、跑一次、贴三行）
两者都不许靠「我记得」——那是最脆的一种衔接。
```

## 修补件也是模块：每个都要写清「它什么时候失效」

> 反向定义：不问「它怎么起作用」，只问「什么情况下它等于没有」。
> 写不出失效条件的修补件，等于没装。

| 修补件 | 补哪条接缝 | **失效条件（它就是哑炮的时候）** | 现在靠什么挡 |
|---|---|---|---|
| `start.ps1` | 开工四件容易漏跑 | 我根本不运行它 —— 它没有触发器 | AGENTS 第一条写了「默认用它」；`verify` 的 wake 留痕项会报「N 小时前」 |
| `log.ps1` | X→M（改了没记） | 我忘了跑它 —— 同样没有触发器 | `verify` 第 31 项实时报「上次记录后又改了 N 个文件」← 这个是真挡 |
| `verify` 各检查项 | 全部结构项 | 检查项被覆盖 / 正则写错 / 项数变少 | 第 26 项「检查器自检」数项数；`probe.ps1` 用假错试 |
| `pin` 对账 | M→V（值变了没更新） | 值变了但没重钉；或重钉把假值钉进去 | 「引脚漂移」提示；但要人去 `-Init`，这一步没有自动挡 |
| `attrib.ps1` | 归因无引文 | 归因词没覆盖到（换了说法就绕过） | 词表是硬编码，换说法即失效 —— **已知弱点** |
| `intake.ps1` | 断言无出处 | 只支持 file / user 两类；cmd / api 没做 | 没有 —— **已知缺口** |
| `predict.ps1` | 事后解释冒充检验 | 登记了但到期没人判 | `verify` 第 28 项报「逾期未判」← 这个真有挡 |
| `probe.ps1` | 检查器是哑炮 | 探针自己写错（假错其实不假） | 没有 —— **已知缺口** |

### 从这张表读出来的三件事

```
① 有「自动挡」的只有三个：log.ps1（靠 31 项）、predict.ps1（靠 28 项）、probe 相关的项数自检
② 没有挡的：start.ps1 和 log.ps1 都缺触发器 —— 靠的还是我主动跑
③ 明确的已知弱点：attrib 的词表、intake 的两类来源、probe 自己的假错是否真错
```

**结论：我们补的是「能被检查的接缝」，剩下三个是「靠自觉的接缝」——那三个才是最该下一步动的。**
