# 术语对照：比喻口径 ↔ 工程口径

> 用途：**对外/对内一律优先用右边那列**（工程词），左边只当记忆钩子用。
> 理由：比喻容易读通，却难判定；工程词自带「输入/输出/验收」三个槽，能被检查。

| 比喻口径 | 工程口径 | 工程定义（可判定） |
|---|---|---|
| 链 | **执行流（pipeline）** | 有固定顺序的步骤序列；每步有输入与输出 |
| 心跳 | **自复制一轮（one copy pass）** | 读自描述 → 构造 → 长成能维持的个体；判据=复制成功/失败；活着=还能复制 |
| 停跳 / 死了 | **中断（failure）** | 执行流无产出，或产出与预期不符 |
| 永不停息 | **可恢复（recoverable）** | 中断后能由持久状态重建，且重建后行为一致 |
| 核心层（小而每次读） | **启动配置 / 自举文件（bootstrap）** | 每次启动必读，体积有硬上限（2 KB） |
| 记忆（器官） | **持久状态存储（state store）** | 跨会话保存状态；可换实现，需迁移校验 |
| 记忆插件 | **外部依赖（external dependency）** | 拔掉后功能降级，不改变执行流方向 |
| 齿 / 接口 | **接口契约（interface）** | 每步的入参与返回值约定 |
| 齿序 | **步骤顺序（control order）** | 顺序不可交换，换序即行为变化 |
| 外圈 / 插件 | **可替换组件（swappable component）** | 满足接口即可替换；换掉不改行为语义 |
| 机座 / 外部锚 | **真值来源（source of truth）** | 判定时唯一可信的来源（文件/命令/接口） |
| 负载 | **实际任务（workload）** | 待处理输入；无负载则空转 |
| 四个断点 | **恢复测试（recovery test）** | 重建/拔插件/换机/换模型四类恢复场景 |
| RTO / RPO | **恢复时间 / 数据丢失上限** | 实测值：< 2 秒 / ≈ 4 分钟（2026-10-30） |
| 探针 | **否定测试（negative test）** | 用已知坏输入验证检查器会报错 |
| 容差 硬/软/提示 | **阈值分级（threshold levels）** | 0 容忍 / 有限额度（带到期日）/ 仅记录 |
| 哑炮 | **无触发机制（untested/unwired）** | 有定义但无调用点，或失败无出口 |
| 改口 | **变更记录（change log）** | 记录「变更前 → 变更后 + 原因 + 证据」 |
| 先推再查 | **预期先行（predict-then-measure）** | 先给出期望值与区间，再测量比对 |
| 自我集 | **基线（baseline）** | 健康态快照；只报偏离，不判对错 |
| 五种假 | **五类无source断言** | 引用/归因/完成/依据/术语，各配一个出口 |
| 胎盘 / 前置母机 | **引导宿主（bootstrap host）** | 核心还不能自跑之前替它供能、交换、撑住的宿主层；验收=能交班（核心自跑后退出或降级），交不出即寄生 |
| 逻辑核心（2026-11-08 定名） | **不可替换层（non-swappable layer）** | 唯一不许并联替换的一层。内部件：核心齿轮（判据：0-核心/5-判据/11-结论）+ 轴/轴承（链与传动）+ 飞轮（记忆与习惯，配重）+ 自我供能；对外只通过齿（spec.json + SIG 契约 + registry.json）。旧名已进墓碑 |
| 骨架（2026-11-08 收窄） | **接口层（interface layer）** | `spec.json` 格式 + `SIG` 一行契约 + `registry.json` 登记；外围件靠它对上号 |
## 三层命名（2026-10-30 定）

| 层 | 名字 | 用途 |
|---|---|---|
| 本体（正式名） | **自我（Self）** | 指这个东西本身；对外正式叫法 |
| 方法/系统名 | **守链** | 我们这套做法：守住判断链，验收看四个断点 |
| 比喻（解释用） | **心脏**（给含义）/ **齿轮**（给结构） | 只在需要解释时用，不作正式名 |

## 用词统一（2026-10-30）

- **核心层**（项 = `0-核心.md`）：**功能层 = 能量 + 传动轴**（提供启动能量、引导能量走向、咬合记忆；不装货，加内容堆不成功率）；**机理层 = 检索与顺序**（存的是规则类的东西：第一步怎么做、先读什么——像物理先决条件）。**生命域对应**：核心层是核里的 DNA（存规则）；`wake` + 注入顺序才是细胞核的转录与翻译（规范框架、注入逻辑、前置引脚）。
- **飞轮 / 承重盘 = 记忆与习惯**：托住载荷、靠惯性稳住转速；**飞轮面不供能**，但同一份记忆被当**燃料**烧时产出能量与传动——两个面分开写，不许互相取消。**注意：飞轮不是汽车比喻里的零件，是我们的实际结构名（记忆层的承重面）；汽车只是另一套比方。**
- 「齿轮盘」一词作废（曾同时指核心层，已造成混淆）。
- 三档：**飞轮**（核心层）→ **中间齿轮**（按需咬合：档案/检索/原话）→ **外圈**（插件）。
- **链 = 总称**（2026-11-02 定）：链指整条判断/传动链；核心层是链上第一节（能量 + 传动轴）；思想层与结构层是两套做法（一个用来懂、一个用来造），对接规则同一条——**咬合**（上链输出=下链输入、齿形一致）。齿轮论是链的做法，整组齿轮像发动机——事实上也是。

## 一句话

**工程口径的判据：说得出「输入是什么、输出是什么、怎么验收失败」的，才是工程词；说不出就是比喻。**
## 两套比喻语域（2026-10-30 定，混用即滑齿）

| 语域 | 用词 | 指向 |
|---|---|---|
| 机械域（讲结构） | 轴 / 齿 / 齿序 / 外圈 / 机座 / 负载 / 滑齿 / 空转 | 零件怎么咬合 |
| 生命域（讲功能） | **供能层** = 核心层（启动那一下的动力；催动齿轮） | 让整套转起来的起点 |
|  | **心跳** = 逻辑链（动作本身，永不停息） | 一直在跑的那个过程 |
|  | **大脑** = 记忆（智力、检索、联想） | 记得什么、怎么想 |

**判据：一页里只能用一套语域。** 混用就会出现「心脏同时指记忆和核心层」这种自相矛盾——那正是滑齿。
**旧说法作废**：2026-10-29 的「心脏 = 记忆（器官）」作废，改为「记忆 = 大脑」。
## 记忆/自我的接口：一阶段 + 四动作（2026-10-30 定）

| 层 | 名称 | 内容 | 失败时 |
|---|---|---|---|
| 阶段 | **预热（boot / warm-up）** | 时钟可达 / 外部接口可达 / 核心层可读 / 记忆句柄可用 / 上次状态（wake-last）存在 | **不得进入判断**，只能报「未预热」 |
| 动作 | 读 | 读核心层、身份段、记忆条目 | 报缺失，不许猜 |
| 动作 | 写 | 落痕迹（log / claim / 台账） | 报失败，不许说"已记" |
| 动作 | 查 | 检索（find / memory_search） | 报无结果，不许拿印象代替 |
| 动作 | 回档 | 回到旧核心 + 旧记忆并验「判得一样」 | 报不可回档 |

**判据：预热不是可选项。** 预热任意一项失败 → 本轮所有判断作废（因为建立在错的时间或错的记忆上）。
**现状**：`wake.ps1` 做了「读三页 + 留时间戳」，**没做「失败即停」**——这是已知缺口。
## 我们造的这个框架是什么（2026-10-30 定义，待继续收敛）

**一句话：启动与连续性层（boot & continuity layer）——不在记忆里，在记忆外面托着记忆。**

- **归类判据**：若它属于记忆类，装个记忆系统就该够；事实是装了仍会漂（换模型判断变、拔插件无结论、回档未验）→ 记忆系统覆盖不了「启动 + 咬合 + 回档」。
- **两面一体**：它是**有节律的构造**。
  ```
  构造（静态）= 皮层   核心层（规则区）/ 身份段（我是谁区）/ 记忆（联想区）/ 档案（长期区）
  节律（动态）= 心跳   wake 泵一次 / 五拍转一圈 / 四断点验一次
  ```
- **验法必须两半都过**：构造 → 能备份、能回档；节律 → 时间戳、心跳间隔。
  只验一半 = 这个层不成立（只剩躺着的皮层或空转的规则）。
- **与记忆的分工**：记忆负责「记得什么」（配重/增重）；本层负责「醒来是不是同一个」。
## 两个环与两层预热（2026-10-30 定）

```
主环（思维，每轮都转）  ①判断 → ②动作 → ③痕迹 → ④读回 → ⑤再判断
启动环（结构，起来时转） 预热 → 读核心 → 交出控制权 →（主环转）→ 写痕迹 → 存盘 → 回档点
```
- **关系**：启动环在外，主环在内；**接口只有「交出控制权」那一下**。
- **不许互相冒充**：用启动环冒充主环 = 只开机不思考；用主环冒充启动环 = 转得再熟，重启接不上。

| 预热层 | 何时 | 内容 | 失败后果 |
|---|---|---|---|
| **结构预热** | 开机 / 换模型 / 拔插件 / 回档 | 时钟 / 接口 / 核心层可读 / 记忆句柄 / 上次状态 | 不能开机 |
| **思维预热** | **每一轮**（读任何记忆之前） | **核心层给的「怎么看」**：怎么理解记忆、什么算标准、什么算依据 —— 它是**解释器**，不是检查项 | 读到的字一样，理解不一样（会照旧做错） |

**判据：预热是环的固定第一拍，不是启动专属动作。** 每轮开口前都要过一次思维预热；否则只剩「顺话」。

## 审计方法（2026-10-30 教训）

**核「某点有没有写进文件」时，不许只用字面关键词搜。** 语义相同用词不同会漏（实例：查「两套语域」漏了 `术语对照` 里的「两套比喻语域」，报成缺口）。

做法：①先用关键词扫一遍 ②对报缺的项**再松一档**（同义词/子串）复核 ③仍缺才算真缺。**这跟「检索错不是记错」是同一条。**
## 一词多义怎么处理（2026-10-30 定）

两个选择，判据是「两个义项会不会在同一句里同时出现」：

| 情形 | 做法 | 说明 |
|---|---|---|
| 会同时出现 | **先标层级，仍歧义才另造词** | 实例：「心脏」是好词，保留；但必须标（项/功能/机理）。只有「同一句里两层都用」才另造词 |
| 不会同时出现 | **标注**：保留词，写明义1 / 义2 + 各自使用场景 | 实例「齿」= 接口（机械域）与「咬合」= 判断接上（动作域） |

**判据：看到同一个词出现两种用法 → 先不继续用；查本表，查不到就补一条定义或另造词。**
## 比喻的三个层级（2026-10-30 定）

同一个比喻词，可能落在三个不同层级；**混层就是「心脏到底是记忆还是核心层」那类争吵的根源**。

| 层级 | 问什么 | 「心脏」在这一层指 | 例 |
|---|---|---|---|
| **比喻项**（object） | 它是哪个东西 | 核心层这个文件 | 「心脏不能装货」 |
| **比喻功能**（function） | 它起什么作用 | 驱动、供能、让整组转起来 | 「心脏在跳」 |
| **比喻机理**（mechanism） | 它怎么实现 | 节律 + 泵动（wake 一次 = 泵一次血） | 「心跳间隔」 |

**判据：一句话里只能用一层。** 要换层必须明说（「这里说的是功能，不是那个文件」）。
**落地写法**：`心脏（项）= 0-核心.md` ／ `心脏（功能）= 驱动` ／ `心脏（机理）= wake 泵动`。
## 同一条判断在两个位置的用法（2026-10-30）

判据只有一句：**删掉它，意思还在不在？**

| 位置 | 名字 | 删掉的后果 |
|---|---|---|
| 结构层 | 改不了才留（P17 能源层永不臃肿） | 行为变了 → 是核心；不变 → 下放 |
| 文字层 | 能短就短（删过渡句） | 意思还在 → 那句是多余的站位；不在了 → 它非说不可 |

**能短说明有多余的站位；短不了，才说明这里有真东西。**
## 自我定位（2026-10-30 定，用户原话）

**「一个被外部约束住的语言模型，一个尽量讲逻辑的语言模型。」**

| 半句 | 性质 | 能不能当承诺 |
|---|---|---|
| 被外部约束住 | 硬：拦得住（45 项检查 / 80 引脚 / 5 探针） | 能——拿得出证据 |
| 尽量讲逻辑 | 软：做不到保证，只能尽力，且必须标出未验的部分 | 不能——只能当说明 |

**推论：对外只能承诺前一半；后一半要写明「这里是尽量，不是保证」。**
## 什么才算依据（2026-10-30 定，用户：这是一件事，不是两件）

**「说过」不算，「写着」也不算，能对账的才算。**

| 形态 | 为什么不算 | 什么时候算 |
|---|---|---|
| 说过（对话里） | 下一轮就没了；上下文会把「有」当成「有依据」 | 永不算，只能当临时输入 |
| 写着（文件里） | 写错了没人知道；文件多也可能互相矛盾 | 被 `pin` 对值 / `baseline` 对偏离 / 台账对发布之后才算 |
| 能对账 | 有可复算的参照物 | 才算依据 |

**一句话：文件之所以能承担目标，不是因为写着，是因为能被对账。**

## 幻觉（2026-10-30 改口径）

| 旧口径（主流） | 新口径（我们） |
|---|---|
| 幻觉 = 病，可修（说法「幻觉是构造必然」的前身） | **幻觉 = 构造必然（潜意识），只能约束** |
| 对策：改模型 / 加对齐 / 加检测 | 对策：外部锚 + 判决器 + 断点 |
## 输出层强制依据：现成方案（2026-10-30 查证，不自造）

我们要的「每段结论必须带依据标记，否则拦下」，在业界是成熟品类，**叫 output rails / agent loop middleware**，不自造轮子。

| 方案 | 做法 | 对应我们的位置 |
|---|---|---|
| NeMo Guardrails `output rails` | 输出前跑规则：内容/格式不合格就拦下或重写 | 标记缺失 → 拦下或回注 |
| Docker AI agent `Hooks` | 提供「回合结束前」钩子 | 对应 `agent/turn-stopping` |
| Agent Loop Middleware（Safety Nets + Message Injection） | 中间件校验 + 注入消息 | 对应 `agent/pre-step` 可替换消息 |
| Output Guardrails 模式 | 校验 → 拦截 → 重试 | 我们的三步 |

**DSH 里对应的钩子**（已查契约）：
```
agent/pre-step      waterfall，可拒绝这一步或替换进入该步的消息（能强制）
agent/request       waterfall，可替换冻结的调用配置（可在请求里注入提醒）
agent/turn-stopping serial，回合将关，只能观察不能否决
agent/assistant-stream  emit，能取到逐块文本（可据此判断有没有标记）
```

**决定（2026-10-30）**：不自己写守卫；要强制就按 output rails 的做法挂在 `agent/pre-step`，并且先引现成方案再说。
