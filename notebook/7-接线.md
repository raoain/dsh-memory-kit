# 接线层 · 什么算「接上了」

> **拍② 动作**｜接口：读完知道这东西算不算接上了

> 这一页管一件事：**写出来的东西，有没有接到会触发它的地方。**
> 这一页的核心词是**哑炮**（旧称悬空）。**定义只写在 6-话.md 一处**，这里只引一句：存在、但不被触发、且失败无人知道。
> 英文检索仍用 orphan / dangling reference（它们只描述形状，不描述后果）。

---

## 一、接线三问（任何东西落地前都要能回答）

```
① 谁触发它？    人 / 脚本 / 定时 / 下一轮注入 / 某个事件的回调
② 什么时候？    每次开工 / 收工 / 改规则时 / 翻旧文件时 / 永不（那就该删）
③ 失败谁知道？  哪个检查项会红 / 谁会看到 / 没有出口 → 哑炮
```

**第三问答不上来的，一律算哑炮。** 前两问只是「有没有人用」，第三问才是「断了会不会被发现」。

## 二、三档强制（强度从高到低）

| 档 | 是什么 | 例子 | 我们的现状 |
|---|---|---|---|
| ① 格式强制 | 生成时填不出就产不出（事前） | 断言必须带 `来源:` 字段 | **几乎缺** |
| ② 检查强制 | 写完有人查，报红（事后） | `verify` 23 项 / `pin` 46 项 / `lint` / `attrib` | 有 |
| ③ 提醒自觉 | 写条规则提醒自己 | 便签、AGENTS 里的话 | 依赖过多 |

**2026-10-29 通宵的教训：所有翻车都出自①缺位。** 没有格式把关，只能靠②事后抓；抓不到的口头内容（比如随口报的时间）就漏了。

## 三、已知的哑炮案例（本机）

```
5-判据.md / 6-话.md   加了页面，没进 README 导航 → 孤儿
规则写进核心层        没有检查项 → 行为不变（$Keep/$keep 又犯）
判据 P13（证据指针）   标了「未实施」 → 挂着
断言「20 天」         没接来源 → 幻觉
```

**四种形态：孤儿页 / 规则无检查 / 判据未实施 / 断言无来源。** 它们是同一件事。

## 四、落地动作（谁来做）

```
每加一个文件 → 同时在 README 导航里加一行
每加一条规则 → 同时说清「哪个检查项能发现它失效」
每加一条判据 → 立刻标状态：已实施 / 未实施
每说一个数   → 句子里带来源，带不出来就说「不知道」
```
