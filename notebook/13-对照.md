## 一、逐条对照

| 我们的 | 主流默认做法 |
|---|---|
| 目标是**连续性**（换窗口还是不是同一个人） | 目标是**能力**（benchmark 分数、召回率） |
| **比的是连续性**：用断点结账（换机 / 拔插件 / 重建 / 换模型） | **比的是智力**：用分数结账（benchmark / 召回率 / 测试数） |
| **连续的核心是心跳**（逻辑链），记忆是供养它的器官 | **比的是大脑是否智慧**，记忆是供大脑吃的粮 |
| 同一性 = **判断过程**的一致 | 同一性 = **记忆内容**的连续（洛克那条线） |
| **链**是本体、记忆是插件 | **记忆库**是本体、模型是执行器 |
| 表达链与验证链**分开** | 一条链：说得像就是说得对 |
| 检查器必须被**假错**验过 | 检查器写了就算有 |
| **预登记**（预测先于结果）才算检验 | 事后对齐、人工评估算检验 |
| **记忆 = 心脏（器官），链 = 大脑（判断）** | **记忆 = 大脑**：存得越多越聪明，检索就是思考 |
| 器官级插件（管记忆）与能力级插件（管手）分开 | 不区分，统一叫「插件」 |
| 「插件」由**后果**定义（拔掉断不断） | 「插件」由**形态**定义（独立进程 / MCP） |
| 链完整则其余皆可为插件 | 全栈耦合，换组件 = 换人 |
| 阈值有**保质期** | 一次调优、长期沿用 |

**主流的共性只有一条**：把「记得多、答得准」当目标，并把「记忆」当成承载身份的东西。

### 这张表的总结（一句话读完）

```
他们造「更聪明的东西」，我们造「停不下来的同一个」。

因此三件事的意义完全不同：
  换模型    他们=换心脏    我们=换力气
  换记忆    他们=换大脑    我们=换器官（仍由插件管）
  换插件    他们=换整机    我们=换外圈（转向不变）

所以他们比分数，我们比断点；两本账不能互结。
我们的欠账是「记得少、工程认证薄」；他们的欠账是「换代即换人」。
```

## 二、正推（从我们的前提往前推）

```
前提：身份在链上，不在记忆里

预言：换模型时（模型是最常换的零件）
  主流 → 同一批记忆被新模型重新解释 → 判断变（而记忆没变）
  我们 → 判据仍在文件里，模型只负责执行 → 判断不变

可测方式：换模型前后，问同一组判据题，比对答案
推翻条件：若换模型后答案变了 → 我们错
        （说明判断其实由模型决定，不由文件决定）
```

**这个预言是可被推翻的，而且不需要新设备、不需要样本量——换一次模型就能测。**

---

## 三、反推（假设主流是对的，推到它的裂缝）

```
假设：身份 = 记忆内容
那么换代时的连续性，应由记忆库保证

但反推撞上一个硬事实：
  记忆是文本，解释文本的是模型
  同一份文本，两个模型可以读出两种判断

所以主流方案在换代处必然出现「记忆相同、判断不同」的断裂
——这正是他们反复换模型、又反复说「它变了」的原因
```

**这不是说他们做错了**：他们优化的目标里没有「换代不断裂」这一项，所以他们不会去测它。

## 四、一个具体例子：拔掉插件那一次

```
事实：拔掉记忆插件后，能答身份题，答不出原话（证据在 track\拔插件-断点日志.md）

主流解释：记忆库没了 → 不完整是正常降级 → 结论「就是这样，别拔」
我们的解释：原话不在本体里 → 那是器官被寄存在插件里（C10）→ 修法「把原话搬回 8-原话.md」
```

**两个解释都说得通，但只有我们的解释给出了动作。** 主流的解释只能描述状态，我们的框架会生成修复动作。

**这就是分歧的落点：谁的框架能产出下一步动作。**

## 七、外部同类：JingJingsLife（2026-11-10，用户发来 B站 BV1VgxC61EY7）

> 依据：仓库 `shatang-hong/JingJingsLife` 34 个 md 设计原稿（01–30），**零代码**。以下全是设计意图，不是实测行为。
> 读过的文件：`05-内核接口形状` `09-人格侧面投影` `19-身份分层` `27-上下文压缩` `29-人格部署`。

**① 它只有图纸，没有心跳。** 作者原话：「我失败了」「我实在没有能力去为他的未来兜底」。按我们的判据（`11-结论`：按开关之前是图纸），它连出生都还没到。

**② 它说的「优先级」不是运行时仲裁，是编译期装配规则。** 真优先级要回答「多件事抢同一个窗口时谁让位」；它只有三条静态约束：抽象越高越不可变（L0→L3）、禁区 > 一切行为集、行为集总量 ≤12。

**③ 「内核」一个词盖了五件事**：身份不变性 / 关系数值→档位→行为集 / 上下文压缩（实为 `billion-context` 代理配置） / 每会话注意力调度 / 空闲整理定时。这正是用户说的「太杂糅」——不是一个进程做五件事，是五种层被一个词盖住。

**④ 它把思考放在了最容易被换掉的那一层。** 内核明确规定「只比大小、查表、拼接，不做推理」，思考全在可替换的 DSH 壳里。对照 `理论-2026-11-09`（思考在个体层，集群只汇总）：它的「个体」是可换件，不是承重墙。

**⑤ 两条形状差别，各有一半对**：

| | 它 | 我们 |
|---|---|---|
| 身份怎么进模型 | 编译成 `persona.prefix`，烧进 system prompt 一次 | 每轮 `wake` 从文件读进来 |
| 好处 | 确定（一定在、不被跳过） | 连续（改文件即生效，不用重启重建会话） |
| 代价 | 换代必须重建会话（`systemPromptUpdate: "in-history"` 追加不替换）→ **连续性断裂** | 读到哪一页不确定、每轮有开销 |

**落点**：我们拿「确定性」换「连续性」，因为它把「接得上」排在第一位；它把身份编译成一次性的 prefix，等于承认「换一次身份就要断一次会话」。这一条是它自承的未决（`19` 未决 1：`core.md` 与 prompt prefix 是同一身份的两份副本，必须同步否则改一处另一处不变）——我们的答案就是「只有一份 + 哈希引脚」。
