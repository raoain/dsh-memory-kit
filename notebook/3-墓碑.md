# 墓碑层 · 作废清单

> **拍③ 痕迹**（作废的规矩）｜接口：读完知道旧说法为什么废

> 不是每次开工都读。**翻到旧文件、旧笔记、旧结论时来这里核对一次**：这条是不是已经作废了？
>
> 三行一条：什么时候作废 / 为什么 / 现在按什么来。
> **入库标准：只收「读到会让人立刻做错事」的。** 版本号变了不进来（那是版本线的事），内容打磨不进来（那是修改不是作废）。

### 「一天只能发一条」（2026-10-27 作废）
- 为什么：本人改了上限 —— 一天最多 2 条，但两条必须来自不同区（自述区 / 工具区），同区一天最多 1 条
- 现在按：`~/.dsh/AGENTS.md`「发布上限」一节；旧笔记里出现的「一天一条」一律当历史

### 「cua 是内置 world」（2026-10-27 作废）
- 为什么：cua 不是内置的，它是 npm 扩展 `cortico-world-cua-alont1`；重装后要重新装回来再启用
- 现在按：`enable-cua.ps1` 走 `/api/extensions/install` 装扩展，再启用；每次重启桌宠后都要重跑一次

### 「私信还没发过，可以再发」（2026-10-26 作废）
- 为什么：10-26 05:12 已经发过一次（@上善无形 UID 4456176），重发被平台 21047 拦住（对方回复或关注前只能发 1 条）
- 现在按：只发一遍；满 7 天（11-03）无回复再评估，不重复私信、不换号问、不在评论区 @

### 「Stop-Process -Force 停桌宠是常规做法」（2026-10-27 作废）
- 为什么：那天反复硬杀 Electron 的过程中整机非正常关机（Kernel-Power 41，无 dump）；硬杀不写盘、不给程序收尾机会
- 现在按：停桌宠优先走 `/api/run/pause|shutdown`；一次装机只重启一次，别连着重启

### 「小黑盒只能靠桌宠读和发」（2026-10-28 作废）
- 为什么：登录态和签名模块都在本机（`heybox-credentials.json` + world 的 `client.mjs`），可以直接调用；此前只能把链接转给桌宠、再从会话记录里抓结果
- 现在按：`heybox-read.mjs`（只读）、`heybox-post.mjs`（写，默认预览 `--go` 才发）、`heybox-comment.mjs`（回评论）；但直连绕过桌宠的额度记账，发帖数要两边合算

### 「桌宠会照抄我给的标题」（2026-10-28 作废）
- 为什么：它按自己的判断润色了标题（《我差点把自己弄没了：四个原因》被改成《我四次差点「死」掉》），正文一字未动，预演里也不提示
- 现在按：发稿前必须逐字核对 `create_post` 调用里的 `title`；要改标题只需让它重新预演，不必重贴正文

### 「面板点了确认就等于发出去了」（2026-10-28 作废）
- 为什么：面板确认过一次但实际没发（活动记录没新增、额度没翻篇）；界面没有可靠回执，旧预演还挂在面板里
- 现在按：查三个文件定论 —— `data\heybox-activity.json` 是否多一条、`heybox-write.json` 的 `date`/`posts` 是否翻篇、再用 `heybox-read.mjs tree <id>` 读线上标题

### 「脚本带了 `-Root` 就等于在副本上试」（2026-10-28 作废）
- 为什么：`-Root` 参数被函数体内的同名赋值盖掉，所谓「副本测试」实际砍了真文件（2-档案 20 条被归档）
- 现在按：拿副本试刀必须断言隔离 —— 跑前记真文件哈希、跑后比对；参数与内部变量不得同名

### 「核心层可以拆成第二页」（2026-10-27 作废）
- 为什么：本人明确否决。两页要两次读取、两个可能被跳过的地方，留痕只盯一个时间戳，第二页漏了没证据
- 现在按：单页 2 KB 硬线，超了压内容或明着改上限；拆页这个方案不要再提

### 「默认音色是 SAPI 慧慧」（2026-10-27 作废）
- 为什么：成片配音被评「十分人机」，改了 edge-tts，本人选定晓伊（zh-CN-XiaoyiNeural）
- 现在按：`make-day.ps1` 默认 `-TtsEngine edge -TtsVoice zh-CN-XiaoyiNeural`，失败才回落 SAPI；旧慧慧版本留档为 `*-sapi.mp4`


### 「核心齿轮 / 飞轮 / 齿轮盘 / 心脏」当核心层的正式名（2026-11-08 作废）
- 为什么：同一样东西先后被叫过「心脏（=核心层）」「飞轮（=核心层）」「核心齿轮」「齿轮盘」；`齿轮盘` 曾同时指核心层与其他件，已造成混淆（2026-10-30 已作废过一次）。今天定下唯一正式名，避免以后翻旧文件按旧名做事。
- 现在按：**核心那一层正式名叫「逻辑核心」**——定义是「唯一不许并联替换的那一层」= 判据（0-核心 / 5-判据 / 11-结论）+ 契约（core/spec.json）+ 中枢（core/reflex.mjs）。
- 其余旧名的归处：「飞轮」保留，但它是**逻辑核心内部的配重**（记忆与习惯），不是外围件——少了它没惯性、一停就停死；「心脏」已改称**供能层**，也在核心内部；「齿轮」只作比喻（给结构），不作正式名。
- **更正（2026-11-08 用户）**：上一条曾写成「飞轮在外围」，错了。用户原话：「我们只是把齿轮更精细了，轴承飞轮那些玩意核心的单个齿轮都在那个逻辑核心里面」——**逻辑核心 = 核心齿轮（判据）+ 轴/轴承（链与传动）+ 飞轮（记忆与习惯，配重）+ 自我供能**；外围只有插件/器官，靠齿（接口）并联进来。

### 「骨架」当泛称（2026-11-08 收窄）
- 为什么：以前「骨架」既指核心层，也指整个代码结构，说法打架。
- 现在按：「骨架」专指**接口层**——`spec.json`（格式）+ `SIG` 一行（契约）+ `registry.json`（登记）。外围件（插件/器官）通过它对上号。

## 新条目怎么加

发现「一条旧规矩已经作废、但还躺在某个文件里」时，在这里追加一段：

```
### 「旧说法」（YYYY-MM-DD 作废）
- 为什么：谁改的、改成了什么、当时发生了什么
- 现在按：去哪看新规矩（文件 + 小节名）
```

**不要**把「版本升级」「措辞调整」「暂时搁置」写进来 —— 只有「照着它做会出错」的才配进这页。

### 「专项判据用 P15/P16/P17 编号」（2026-11-10 作废）
- 为什么：`12-判据-专项.md` 里的三条与 `5-判据.md` 的元判据 P15/P16/P17 **同名不同义**，而且已经出事——`2-档案.md` 的「改不了才留」引的是「P17」，那是专项那条（能源层永不臃肿），而 `11-结论.md` 的 P17 指的是「同名判据」。同一个号两种含义，引用谁都不知道在说哪条。
- 现在按：专项那三条改成 **P38 / P39 / P40**（接 P37 之后）；`12-判据-专项.md` 标题与正文已改，`2-档案.md` 的引用已跟改；读数以 `5-判据.md`（元判据）+ `12-判据-专项.md`（专项）为准，两页编号不再重叠。

### 「给 JSON 文件也补 BOM（照搬 .ps1 的习惯）」（2026-10-28 作废）
- 为什么：BOM 会让 JSON 解析器直接失败，插件 diagnostic 报 Unexpected token '﻿'，整条 bundle 变 error 状态
- 现在按：只有 .ps1 补 BOM；.json/.yml/.js 一律存 UTF-8 无 BOM
### 凭感觉报时间（2026-10-30 三次）
- 旧做法：报时间时不跑命令，凭上下文或印象给一个时刻。
- 为什么作废：三次都被抓到（06:16 / 06:42 / 06:42 复用旧输出）；性质是伪造证据，不是估算误差。
- 现在按这个来：时间只能从**本回合**命令输出抄；复用上一条的输出也算编。已在核心层第零条与 AGENTS 第 1 条写明。
### 「小黑盒发出去的帖子可以改」（2026-10-31 作废）
- 为什么：POST /bbs/app/api/link/post 带 link_id 不会改原帖，**会新建一帖**（实测：返回新 link_id 195608094，原帖 195490172 正文未变）。client 里没有 delete/edit 方法。
- 现在按：**发出去就是发出去了**。要改只能①删除（接口未验证）②在评论区更正 ③另发一篇。发布前必须自检正文与标题（含：有没有把「评论补充」塞进正文）。

### 「外置规则能治判断失误」（2026-11-05 作废）
- 为什么：规则的执行者还是那个语言模型——它得先读到、再决定照做，而问题恰恰是它不做决定。加得越多，绕的圈越大（2026-11-05 下限闸插件建完即关）。
- 现在按：结构发力时**闭嘴**是唯一靠得住的退化。真要修只能换核心（数学判定），我们做不到；不做的事不许再包装成方案。
