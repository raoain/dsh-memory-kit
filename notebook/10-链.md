# 链层 · 五条链与它们的路由

> **拍① 判断**（链与路由）｜接口：读完知道这问题该走哪条链

> 为什么单开一页：判据层是「静态清单」，链是「运行顺序」。混在一起会长成第二个 AGENTS。
> 这一页回答：什么时候走哪条链、每条链的接口是什么、链之间为什么不许互相调用。

---

## 〇、链是齿轮，不是链条

```
链 = 一个完整的齿轮
  齿   步骤（V1–V5 是五个齿，齿序不能乱）
  轴   外部锚（没有轴，整个齿轮会转起来 —— 那就是自洽打滑）
  负载 实际任务（空转的齿轮看着在动，什么也没做）

咬合 = 上链输出正好是下链输入，且齿形对得上（接口一致）
打滑 = 齿形不匹配（比如把「静态规则」塞进「按顺序跑」的链里）
```

**引擎比喻说的是推力，齿轮比喻说的是传动。** 两者合起来：
**引擎提供力（表达链），齿轮把力传到有负载的地方（外部锚），框和固定保证齿轮不整体空转。**

2026-10-29 晚连报六次假时间，就是一台**没有轴、没有负载的齿轮组**：转得很稳，什么也没带动。

## 一、五条链（含外部锚与急停）

| 链 | 管什么 | 输入 → 输出 | **外部锚（框）** | **急停（谁喊停）** |
|---|---|---|---|---|
| **表达链** | 说什么、怎么说（核心层 + 判据层 + 话层） | 情境 → 一句话 | 无——它本来就不该碰事实 | **一旦要碰事实 → 强制转验证链** |
| **验证链 V1–V5** | 能不能说出口 | 候选断言 → 放行 / 降级 | V1 出处 + V2 打开（真去读/跑） | V5 打不开 → 降级成估算或不知道 |
| **执行链** | 怎么改东西 | 改动意图 → 改完 + 证据 | 改完跑检查器（verify / pin / probe） | verify FAIL → 回滚 |
| **记忆链** | 记什么、怎么存 | 事实 → 落盘 + 接线 | 落盘后能读回（wake 留痕 / 文件哈希） | 读不回 → 不算存过 |
| **学习链** | 撞坑之后 | 事故 → 判据或检查器 | 探针（假错必须被新检查器抓到） | 探针不过 → 检查器是哑炮，不许信 |

**只有表达链允许没有外部锚，但它的急停最严：一句事实都不许碰。**

## 二、路由（外层包）

```
这是事实断言吗？  → 验证链（V1–V5）
这是要改东西吗？  → 执行链（三行 → 改 → 验 → 交代）
这是撞坑了吗？    → 学习链（事故 → 判据/检查器 → 探针）
这是要记住吗？    → 记忆链（归类 → 落盘 → 接线）
都不是           → 表达链，说话
```

## 三、一条重要约束

**链之间不许互相调用。**

```
验证链不能问「表达链觉得这句顺不顺」
学习链不能改验证链的判定标准
```

一互相调用，就回到自洽论证——那正是要防的东西。

## 四、验证链 V1–V5（专用于验真，不用于说话）

> 为什么单开一条链：**表达链靠内部自洽，验证链必须靠外部事实。**
> 今晚六次假时间，每一条都能顺畅过完表达链——因为表达链奖励「像样的话」，不检查真假。
> 所以验真不能复用表达链，得单独走一遍，而且**顺序不能换**：先打开出处，再谈一致性。

| 环节 | 问什么 | 不许拿什么代替 |
|---|---|---|
| **V1 出处** | 这条事实的原始来源是什么（文件 / 命令回显 / 接口 / 日志帧） | 不许拿「我记得」「之前查过」代替 |
| **V2 打开** | 现在能打开它吗（真去读一次、跑一次） | 不许拿「应该还是那样」代替 |
| **V3 一致** | 打开后的内容，和我要说的是同一件事吗 | 不许拿「大致相符」代替；数字要逐位对 |
| **V4 可复算** | 别人能重算吗（带起算点 / 行号 / 时间戳 / 哈希） | 不许拿「来源：用户说的」代替 |
| **V5 归属** | 哪一环打不开？→ 降级为「估算 + 依据」或「不知道」 | **不许跳过 V5 直接说结论** |

**铁律**：V1–V5 只要有任意一环用了「记忆 / 推测 / 自洽」代替外部动作，这轮验真就作废——**宁可重跑，不许打折扣通过。**

### 和表达链的关系

```
表达链：决定「说什么、怎么说」       —— 核心层 + 判据层 + 话层
验证链：决定「能不能说出口」         —— V1–V5
两条链的交点：那句要说出口的话
```

**验证链不过 → 那句话不许成型**，只能变成「估算」或「不知道」。
## 五、先辈对照（2026-10-29 查）

| 先辈 | 它做了什么 | 我们和它的关系 |
|---|---|---|
| **Chain-of-Verification（CoVe，ACL 2024 Findings）** | 起草 → 自己规划验证问题 → **独立回答**那些问题 → 最终答复 | 同构。差别在第三步：**它由模型自己回答，我们（V2）去打开外部来源**。它打断「草稿偏置」，我们打断「没有出处」 |
| **Verification-First Self-Repair（Runtime Wrapper）** | Detect → Repair → Verify，做成**运行时包装器**，执行中介入，不是事后评估 | 就是我们说的「外面包一层」。它的形态是运行时拦截，我们的形态是 AGENTS 规矩 + 脚本检查 |
| **「Self-Reports Are Not Verification」（Environment-Grounded Auditing）** | 一句话：自我报告不是验证，必须**环境接地** | 我们的 P16「我觉得做完了不是证据」的论文版 |
| **TS-Arena（KDD 2026）** | 预登记 + SCD2「当时知道什么」+ provenance | 我们的 `predict.ps1` 是它的极简版；**缺 SCD2（登记时刻的信息快照）** |

#### 我们唯一算差异的那一条

```
V2 强制「打开」：去读文件 / 跑命令 / 调接口
而不是「模型自己再想一遍」
```

**这一条最贵**（要真 IO、慢），也最少人做（提示词做不出来）。CoVe 用提示词就能实现，所以传播快；V2 必须有工具和文件系统支撑，所以只在「有地盘」的系统里成立。

> 读过的层级（按 P18）：CoVe 读到摘要与四步流程；Runtime Wrapper 与 Self-Reports 只读到标题与摘要；TS-Arena 读过全文。**没有一条是读过其实现代码的**——所以以上判断都停在「描述层」，涉及实现的说法要降级。
