💡 AI Agent 记忆与上下文优化方案
一、 背景与痛点
· 场景：在 QQ 等平台上部署具有个性的 Agent（如 DeepSeek 模型）。
· 痛点：Agent 难以记住长期发生的事。单纯依赖大模型的“上下文压缩”效果不佳，容易丢失细节；而全量输入会导致 Token 数量“线性爆炸”，成本极高且超出模型窗口限制。
二、 核心架构：外挂长期记忆库
· 存储介质：将所有的历史会话，持续记录并汇集成一个超大的 Markdown (.md) 文件。作为 Agent 的外挂“海马体”。
· 检索器：引入一个轻量级的小模型（约 3B 参数）专门负责记忆提取。当用户发起新对话时，由这个小模型去遍历/检索那个超大的 md 文件，根据当前对话的语义，对历史记忆进行相关度打分与排序。
三、 上下文构建策略（输入源的组合）
为了保证既不失忆，又不撑爆显存，将筛选后的记忆分为三类，混合注入到主模型的输入（Input）中：
1. 强相关记忆（Top N）：小模型打分最高的前 N 条。保证 Agent 能精准接住当前的话题和梗。
2. 弱相关记忆（弱 Top N）：排名靠后但仍有相关度的 N 条。提供边缘背景信息，丰富回答层次。
3. 随机记忆（Random N）：从未被选中的记忆中随机抽取 N 条。
· 作用：模拟人类大脑的跳跃性思维和随机联想，增加 Agent 的“灵光一闪”和拟人感，防止回答过于死板。
四、 进阶优化：引入“时间权重”维度
除了语义相关度，还要把时间（Time）作为核心筛选因素加入小模型的排序逻辑中：
· 时间衰减：越近期的记忆权重越高。
· 时间聚类（高频事件）：如果某天针对某个关键词的聊天频次极长/极高，说明该事件极其重要，提取该“时间块”的整体记忆。
· 绝对日期权重：对于特定的重要日期（如纪念日），赋予极高的提取优先级。
五、 方案优势总结
1. 性能与成本平衡：3B 小模型可以做本地化部署（如 Ollama），零 API 成本；只把筛选后的片段送入大模型，大幅降低 Token 消耗。
2. 拟真度极高：通过“强+弱+随机”的搭配，完美模拟了人类大脑“精准回忆 + 模糊印象 + 随机发散”的记忆模式。
3. 可扩展性：通过按时间戳对 md 文件进行分块（Chunking），可以结合轻量级的关键词过滤（如 BM25）作为第一层粗筛，进一步降低 3B 小模型的计算压力。
