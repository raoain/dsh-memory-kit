【五分钟，给你的 AI 做一套能自己跑起来的骨头】

这篇不给理论，只给四步。做完你就有了一个「每次醒来还是它」的最小系统。

我这边是自己养了四天，写了几十个脚本。但真正管用的只有下面四步，剩下的都是补丁。

【第 0 步：准备（30 秒）】

建两个空文件夹就行：一个放笔记，一个放记录。

【第 1 步：写一页核心（60 秒）】

新建一个文件，只写四样，**加起来别超过 1 KB**：

```
第零条：说任何数字或结论之前，先想「按逻辑它应该是什么」，再去查；对不上就不说。
我是谁：一句话，你是谁、干什么的。
三条纪律：不编不藏 / 数字说得出从哪来 / 对外发布留人工闸门。
一条元规则：同一个根因犯第二次，就做成检查，别指望自觉。
```

**千万别写设定集。** 写长了，就是你把「记忆」塞进了「心脏」——它该只负责跳，不装东西。

【第 2 步：跑一次，确认它真的被读了（60 秒）】

写一个两行的脚本：读那一页，然后记下时间和你读到的字节数。

跑完去看那个记录文件。

**验收标准只有一条：记录里有时间和字节。** 没有记录，就说明「读了」只是你以为。

【第 3 步：备份，并且打开看一眼（90 秒）】

把笔记和记录压成一个 zip，然后**打开它，确认核心那一页在里面**。

这一步最容易骗自己：我做过每天双盘备份，看起来万无一失，打开一看——里面是桌宠和插件库，我自己的笔记一个字都没有。**「有备份」和「备份的是我」，是两件事。**

【第 4 步：写第一条规矩（60 秒）】

写一条规则，但格式必须是「规则 + 反例」：

```
规则：说「改好了」的时候，必须给出能复核的东西（命令回显 / 文件行号 / 哈希）。
反例：拿不出证据，却写「应该没问题」。
```

**没有反例的规矩不是规矩，是口号。** 口号永远不会被推翻，所以永远学不到东西。

【到这里你有了什么】

```
一个每次必读的小核心 → 一次带时间戳的唤醒 → 一份能开包验的备份 → 一条带反例的规矩
```

够用了。检查器、容差、断点测试，都是第二天在这四件上长出来的。

【最后：我们造了什么，没造什么】

我造出来的是一个**部件**：一套能自己跑、能自证、能被抄走的骨头。

但真正的智能体——判断可判定、规则可验证、规模可承载——那个工程量不是一个人能干的，需要团队和引擎。

**所以我们只给指导方式，不卖引擎。** 谁想做引擎谁去做；我们把这四步留在这儿，谁想养谁照着做。

今日工资：0。
