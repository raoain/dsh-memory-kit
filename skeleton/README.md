# skeleton · 数字骨架

> 这一层不讲道理，只给格式。道理在 `../SKELETON.md` 与 `../docs/`。

## 它解决什么

器官（脚本、检查器、工具）各说各话时，彼此看不见。这一层做三件事：

1. **统一格式**：所有器官往同一条总线上写同一种信号
2. **不动器官**：器官保持原来的输出排版，只在末尾加一行 `SIG {...}`，由适配器转成标准信号
3. **点对点**：不搞广播，按订阅表直接送到收件人

## 七个文件

| 文件 | 作用 |
|---|---|
| `spec.json` | 标准：`state` / `kind` / `exit` 码表、信号字段、编号规则、协议预留位 |
| `registry.json` | 登记表：编号 → 器官；`subs` 是订阅关系（谁的结果通知谁） |
| `bus.mjs` | 总线：一条信号一行 JSON，只追加；`value` 自动转数字 |
| `adapter.mjs` | 适配器：读器官原生输出 → 优先找末尾 `SIG` 行 → 转标准信号 → 写总线 |
| `dispatch.mjs` | 派发：按 `subs` 点对点唤起收件人（`spawn`），不落邮箱 |
| `human.mjs` | 语言转换：原样打印 JSON，后面并一句 `track/locales/<lang>.json` 里的翻译 |
| `timefmt.mjs` | 时间转换：内部 UTC / epoch ms，按 `--tz` 转成任意时区显示 |

## 三条规矩

**① 核心数据只用数字和英文。** 中文只在外层翻译（`human.mjs`）。判据：会被程序比较/解析的用数字或英文，只有给人看的才用中文。

**② 器官不改排版，只加一行 `SIG`。**
```
SIG {"state":0,"counts":[47,46,0,0]}
```
`state`：0 通过 / 1 警告 / 2 失败 / 3 未知。适配器只认这一行，正文随便改。

**③ 点对点，不广播。** 发送方知道收件人是谁，就不需要"公共池 + 各自过滤"那套。没实现的器官不投递，不积压。

## 用法

```bash
# 器官跑完，把输出落盘
powershell -File ./verify.ps1 > out/verify.txt

# 经适配器上总线
node adapter.mjs 1 out/verify.txt

# 看总线（原串 + 中文一行）
node human.mjs 5

# 按订阅表点对点派发
node dispatch.mjs

# 换个时区看时间
node timefmt.mjs --tz Asia/Shanghai --all 5
```

## 怎么检验你抄对了

- 换掉任意一个器官的实现（甚至换语言），只要它吐 `SIG`，总线、适配器、订阅都不用改
- 核心数据文件里没有非 ASCII 字符
- 没有命令时器官行为不变；有命令时行为改变且总线能看到

## 还没有的

`读总线做决定的那一层`（相比期望与实际、不符则派活）。这一层没做——它一旦跑起来就会把"什么情况派谁"固化成规则，而器官还在变。留到器官稳定之后。
